## Scope boundary with plan 02-02 (CRITICAL — do not cross)

This plan resolves paragraph/run properties through the basedOn chain and returns deep-merged clones. It does NOT:

- **Concretize theme colors.** A resolved `CT_Color` with `ThemeColor != nil` is passed through UNCHANGED. The `themeEnumToElement` map, `theme1.xml` parse, tint/shade math, and `out.ThemeColor = nil` clearing all belong to plan 02-02's `theme.go`. This plan's resolver must not touch `CT_Color.ThemeColor` / `ThemeTint` / `ThemeShade`.
- **Merge numbering level pPr.** A resolved `CT_PPr` with `NumPr != nil` keeps `NumPr` as-is. The `numId + ilvl → CT_Lvl → merge lvl.PPr into effective pPr` step (D-13) and the `CT_Num.LvlOverride` struct extension (RESEARCH Pitfall 4) belong to plan 02-02's `numbering.go`. This plan's resolver must not parse `numbering.xml` or extend `CT_Num`.
- **Walk `next` chains.** `CT_Style.Next` is an editor-cursor hint, never an inheritance chain (RESEARCH Pitfall 1). This plan's `collectChain` reads `BasedOn.Val` only.
- **Consult `link` for paired character-style rPr.** Optional per RESEARCH Pattern 6; defer to 02-02 if ambiguous. This plan's `ResolveRun` uses paragraph-style-chain rPr + rStyle-chain rPr + direct rPr only.

The resolver MUST leave `themeColor` and `numPr` fields untouched on the merged clone so 02-02 can post-process. Document this in a code comment on `ResolveParagraph` / `ResolveRun`.
</phase_boundary>
