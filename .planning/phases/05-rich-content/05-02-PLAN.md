<threat_model>
| Boundary | Description |
|----------|-------------|
| header/footer content -> OPC part | User-supplied paragraph content serialized into header/footer XML parts |
| header/footer rId -> sectPr | Relationship ID from document.xml.rels linked via CT_HdrFtrRef in sectPr |

| Threat ID | Category | Component | Severity | Disposition | Mitigation |
|-----------|----------|-----------|----------|-------------|------------|
| T-05-05 | Tampering | Header/footer rId collision during template clone | medium | mitigate | Always allocate fresh rIds via dstRels.NextRID() — never copy source rIds directly (Pitfall 6) |
| T-05-06 | Tampering | Missing content type override for cloned header/footer parts | medium | mitigate | Add ContentTypes.Overrides entry for every cloned header/footer part (Pitfall 9) |
| T-05-07 | Tampering | Page orientation swap logic (W > H = landscape) | low | accept | CT_PgSz W/H swap on orientation change. Word reads orientation from W/H ratio, not a separate attr |
| T-05-SC | Tampering | Package installs | high | mitigate | Zero external deps — Go stdlib only |
</threat_model>

<name>Task 1: Header/Footer API</name>
<files>header.go (new), wordingo.go (modify), format.go (modify), template.go (modify)</files>
<action>Implement header/footer creation per D-10 through D-13.

1. format.go: HeaderVariant int const (HeaderDefault, HeaderFirst, HeaderEven) with String() -> "default"/"first"/"even". FooterVariant symmetric.

2. header.go:
   - Header type (ct *wml.CT_Hdr, doc *Document), Footer type (ct *wml.CT_Ftr, doc *Document)
   - X() escape hatch.
   - AddParagraph(text) *Paragraph — appends CT_P to CT_Hdr.P/CT_Ftr.P, dirty=true. Same pattern as Document.AddParagraph but on header slice.

3. Document in header.go:
   - addHelperPart(partName, data, relType, ctType, targetSuffix) (rId string):
     MarkModified, rels.NextRID(), append rels.Rels, ContentTypes.Overrides, return rId.
   - AddHeader(variant HeaderVariant) *Header (D-10):
     partName = "word/headerN.xml". Create CT_Hdr with empty Normal paragraph. Marshal. addHelperPart(..., relHeader, ctHeader, "headerN.xml"). Append CT_HdrFtrRef{ID: rId, Type: variant.String()} to sectPr.HdrFtrRef. Increment nextHeaderID, dirty=true.
   - AddFooter(variant FooterVariant) *Footer (D-12): symmetric using relFooter, ctFooter, FtrRef, CT_Ftr.

4. template.go — OpenTemplateReader header/footer cloning (D-13, reverse Phase 3 Pitfall 4):
   After CloneStyles, before source body copy:
   a. Parse source sectPr for HdrFtrRef/FtrRef entries.
   b. For each ref: lookup source rels by ref.ID, resolve target path, read part bytes, copy to dst via MarkModified, allocate NEW rId via dstRels.NextRID(), add rel entry, add content type, create fixed-up ref with new rId.
   c. Replace defaultSectPr() with source sectPr + fixed-up refs in freshDoc.
   d. Preserve TitlePg (first-page variant) if source has it.</action>
<verify>go build ./... compiles. Test creates header, writes buffer, re-opens, verifies header1.xml part exists in zip. Test footer symmetric.</verify>
<done>AddHeader creates word/headerN.xml + relationship + content type + sectPr link. Header.AddParagraph() adds content. OpenTemplate clones headers with fixed rIds. Round-trip preserves content.</done>
</task>
