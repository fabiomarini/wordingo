<threat_model>
| Boundary | Description |
|----------|-------------|
| hyperlink URI -> relationship | User-supplied URI stored as relationship target in document.xml.rels with TargetMode=External |
| numbering def ID allocation | Auto-generated abstractNumId/numId stored in word/numbering.xml |

| Threat ID | Category | Component | Severity | Disposition | Mitigation |
|-----------|----------|-----------|----------|-------------|------------|
| T-05-08 | Tampering | Hyperlink URI injection via user-supplied string | low | accept | URI stored as relationship target — Go encoding/xml handles XML escaping. Word resolves at render time. No injection path. |
| T-05-09 | DoS | Numbering def ID exhaustion via repeated AddList | low | accept | Add ~2B lists to exhaust int64 IDs. Negligible risk. No guard needed for v1. |
| T-05-10 | Tampering | Numbering def collision with template numbering (numId overlap) | medium | mitigate | Always scan ALL existing NumID/AbstractNumID in parsed numbering.xml; compute maxFound + 1. Start auto numIds at 1 (reserve 0 for Word ListNumber). (Pitfall 3) |
| T-05-SC | Tampering | Package installs | high | mitigate | Zero external deps — Go stdlib only |
</threat_model>

- para.AddHyperlink(text, uri) — creates relationship, CT_Hyperlink with CT_R child
