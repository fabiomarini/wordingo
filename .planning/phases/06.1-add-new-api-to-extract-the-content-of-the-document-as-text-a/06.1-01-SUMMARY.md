# Plan 06.1-01: ExtractText, GFM Parser, ToMarkdown

## Summary

Implemented the text extraction and GFM export methods plus the standalone GFM parser.

### Files Created

- `extract.go` — `ExtractOpts`, `(*Document).ExtractText`, `paragraphText`, `readHeaderParts`, `readFooterParts`
- `internal/markdown/parser.go` — `Parse`, `BlockType`, `Block`, `InlineSpan` types
- `internal/markdown/parser_test.go` — Table-driven tests for all 6 block types and 5 inline types
- `markdown.go` — `(*Document).ToMarkdown` with heading/list/table detection, image embedding, hyperlink resolution

### Key Decisions

- `readHeaderParts`/`readFooterParts` are read-only variants (no `MarkModified`)
- `paragraphText` walks both `CT_P.R` and `CT_P.Hyperlink` child runs
- GFM parser uses position-based inline scanning to avoid bold/italic overlap artifacts
- `ToMarkdown` merges consecutive runs with identical formatting to avoid `****` artifacts
- Image embedding resolves `rId` → OPC part → base64 data URI per DrawingML anchor
- `ExtractText` and `ToMarkdown` do not set `d.dirty` (read-only)
