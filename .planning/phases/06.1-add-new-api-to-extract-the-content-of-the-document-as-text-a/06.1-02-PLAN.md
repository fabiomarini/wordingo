    Create markdown_import.go in root package wordingo. Import set: strings, encoding/base64, fmt, regexp plus internal/wml, internal/markdown.

    Define CreateFromMarkdown(markdown string) (*Document, error) standalone function:
    - Call Create() to get blank document with default styles
    - If err, return nil, err
    - Call blocks, err := markdown.Parse(markdown)
    - If err, return nil, err
    - Call importBlocks(d, blocks) to build content
    - Return d, nil

    Define ImportMarkdown(markdown string) method on Document:
    - nil guard: if d == nil, panic("wordingo: ImportMarkdown called on nil Document")
    - Call markdown.Parse(markdown)
    - If err, store in warnings via d.warn(...)
    - Call importBlocks(d, blocks) to append content
    - Return (no error return per D-12 signature) — parse errors surfaced as warnings, best-effort import continues

    Define unexported importBlocks(d *Document, blocks []markdown.Block):
    - Iterate blocks in order
    - Track active list builder (nil when not in list context)
    - Track code block consecutive mode (for grouping code paragraphs)

    Block handling:
    - BlockParagraph: call d.AddParagraph(content). If content has inline spans (parsed by parser), create runs with formatting. For each InlineSpan: create run via AddRun(text). Apply formatting: if Span.Bold → run.SetBold(true); if Span.Italic → run.SetItalic(true); if Span.Code → run.SetFont("Consolas"); if Span.LinkURL != "" → p.AddHyperlink(Span.LinkText, Span.LinkURL); if Span.ImageURL != "" → decode base64 from data URI and call d.AddImageBytes
    - BlockHeading: call d.AddParagraph("").SetStyle(fmt.Sprintf("Heading%d", block.Level)). Then add runs with inline formatting. If inline spans exist, create runs with formatting; else set paragraph text = block.Content via AddRun
    - BlockCodeBlock: for each line in block.Lines, call d.AddParagraph(line).SetFont("Consolas"). Language hint from block.Language is stored via SetStyle with style name "Code" prefix if desired (agent discretion). Consecutive code blocks NOT grouped for v1 (per RESEARCH.md recommendation — beyond v1 scope)
    - BlockOrderedList: call d.AddList(true). For each block.ListItems (or each item parsed as a single-line Block), call lb.AddItem(text, level). Inline formatting on list item text: parse `**`, `*`, `` ` ``, links (image unlikely in list items). Use regexp to extract spans and create formatted runs per same pattern as paragraph inline
    - BlockBulletList: call d.AddList(false). Same AddItem pattern as ordered
    - BlockTable: call d.AddTable(block.Cells). block.Cells[0] = header row (treated as first data row). Import cells as plain text strings. Agent discretion: inline formatting INSIDE table cells — for v1, import cell content as plain text (formatting parsed inline but applied as bold/italic runs within cell paragraphs). Per RESEARCH.md recommendation: parse inline formatting for cells but skip links/images in cells for v1
      - For each cell string, create paragraph inside cell with inline formatting parsing
      - Access cell paragraphs after AddTable via returned TableBuilder

    Inline formatting parsing for text strings (reuse regexp.MustCompile patterns or use parser's InlineSpan):
    - If the parser already provides InlineSpan on Block.Content, use those
    - Otherwise, re-parse inline content with regexp patterns for bold, italic, code, link, image
    - Build runs: split text by inline pattern positions, apply formatting per span type

    Code block text runs:
    - Code InlineSpan → Run.SetFont("Consolas"). No other formatting applied
    - Link InlineSpan → Paragraph.AddHyperlink(Span.LinkText, Span.LinkURL)
    - Image InlineSpan → p := d.AddParagraph(""); extract data URL (format: data:image/{type};base64,{data}). Split on "," to get base64 data. Decode with base64.StdEncoding.DecodeString. Call d.AddImageBytes("image", decoded, mimeType). AddImageBytes appends image to last paragraph in document. Per D-14: images parsed on import

    Data URI parsing helper:
    - unexported decodeDataURI(uri string) (data []byte, mimeType string, err error)
    - Parse format: data:image/png;base64,<base64data>
    - Split on comma: comma before base64 data. Everything before comma is metadata (mime type from image/xxx portion). Everything after is base64
    - Decode base64 data, return bytes + MIME type

    Error handling per D-16 (agent discretion: best-effort parse):
    - Parse errors → d.warn("wordingo: markdown parse error: %v", err)
    - Continue processing remaining blocks
    - Individual block processing errors → d.warn("wordingo: skipping block: %v", err)
    - Do NOT panic for malformed input
    - Set d.dirty = true after successful import (content was added)
