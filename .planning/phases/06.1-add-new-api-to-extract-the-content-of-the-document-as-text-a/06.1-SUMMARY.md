# Phase 06.1 Summary: Text Extraction & Markdown Conversion

**Status:** Complete
**Date:** 2026-07-26

## What Was Built

### ExtractText (`extract.go`)
- `ExtractOpts` with `ScopedParts` (Body/Tables/Headers/Footers) and `Separator`
- `(*Document).ExtractText` — plain text extraction with part-scoped control
- `paragraphText` — walks `CT_P.R` and `CT_P.Hyperlink` child runs
- `readHeaderParts` / `readFooterParts` — read-only header/footer walking (no MarkModified)

### GFM Parser (`internal/markdown/parser.go`)
- `Parse(input string) ([]Block, error)` — line-based block parsing
- `BlockType` enum: `BlockParagraph`, `BlockHeading`, `BlockCodeBlock`, `BlockOrderedList`, `BlockBulletList`, `BlockTable`
- `Block` struct with `Type`, `Level`, `Content`, `Lines`, `Cells`, `Language`, `ListItems`, `Inlines`
- `InlineSpan` struct with `Text`, `Bold`, `Italic`, `Code`, `LinkURL`, `LinkText`, `ImageURL`, `ImageAlt`
- Position-based inline scanning to avoid bold/italic overlap artifacts
- Table-driven tests: 14 tests covering all block types, inline types, and edge cases

### ToMarkdown (`markdown.go`)
- `(*Document).ToMarkdown` — GFM export with heading/list/table detection
- `paragraphToMarkdown` — heading style detection (Heading1-6), list resolution via numbering.xml, code block heuristic (Consolas/Courier), run formatting with consecutive-run merging
- `tableToMarkdown` — GFM pipe table emission with `| --- |` separator row
- Image resolution: DrawingML rId → OPC part → base64 data URI
- Hyperlink resolution: rId → rel.Target
- Helper functions: `escapeMarkdown`, `escapePipeCell`, `imageMIMEFromHeader`

### Markdown Import (`markdown_import.go`)
- `CreateFromMarkdown(input string) (*Document, error)` — standalone document creation
- `(*Document).ImportMarkdown` — append content to existing document
- `importBlocks` — handles all 6 block types with inline formatting
- `decodeDataURI` — data URI parsing with base64 decoding
- List items support inline formatting (bold, italic, code, links)
